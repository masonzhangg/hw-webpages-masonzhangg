Abstract

We built an interactive real-time demo of glass breaking on a rectangular pane: the user clicks to place an impact, and the system fractures the glass procedurally, turns the pieces into rigid bodies, and draws them with glass-like shading over a simple scene (background image, floor, intact panel). Fracture patterns come from a 2D Voronoi diagram on the glass plane with sites biased toward the hit and scaled by impact energy. Each cell is clipped to the panel outline, extruded to a thin solid, and simulated with our own rigid-body integrator and ground contact response. The interesting design piece is incremental fracture. You can shatter the whole pane or keep subdividing individual shards.

Technical Approach

Fracture geometry (Voronoi on the glass plane). We treat the pane as a planar sheet in 3D with a local 2D parameterization. Seed points for the diagram are generated by FractureSiteGenerator. The first site is exactly at the impact. Additional sites mix mostly uniform samples over the panel with a smaller Gaussian cluster near the impact so the break looks denser at the epicenter. The 2D Voronoi diagram is built with the standard construction: for each site, start from a bounding rectangle and intersect half-planes (perpendicular bisectors to every other site) using Sutherland-Hodgman polygon clipping. That yields convex polygons per site. We then clip each cell to the panel footprint (again convex clipping) and enforce counter clockwise winding for stable downstream use. Relation to prior work. The Interface 2000 sketch on real-time fracture with volumetric approximate convex decompositions (VACD) is about breaking 3D solids into nearly convex pieces suitable for fast collision. We did not implement general VACD or voxel-space fracture. Our geometry is simpler: 2D Voronoi on the midplane + constant-thickness extrusion, which produces convex shards in the plane and extruded prisms. Smith's "Fast and Controllable Simulation of the Shattering of Brittle Objects" mentions brittle shattering with controllable, plausible break patterns rather than a single baked crack. Voronoi breaks are a well-known stand-in for irregular crack networks in games and graphics. We enhanced interactivity with re-fracture: a second hit can subdivide one existing shard by running a local Voronoi build inside that shard's footprint and replacing the parent body with children, including inherited velocity from the parent rigid body so new pieces don't pop out as if the world had reset.

Meshing Shards. Each Voronoi cell is a convex polygon in the panel's 2D parameter space. The builder maps every vertex of that polygon to two parallel copies of the outline in world space: one on the front face and one on the back face, offset by around half the panel thickness along the panel normal. That gives a closed prism-like solid for each shard. The mesh is triangle-based. For each cap (front and back), it computes the polygon centroid, then builds a triangle fan. For the side walls, each boundary edge forms a quad between front and back vertices. The quad is split into two triangles with consistent winding so the mesh is closed has no holes along the rim. Normals are per-face constant (not smoothed across edges), which yields a faceted appearance under lighting. Each ShardMesh also stores cell_uv: the same cell polygon in panel coordinates. That supports 2D point-in-polygon tests on the glass plane for ray-panel intersection, which shard when doing incremental fractures.

Rigid-body Physics. Each chip is a single rigid body: it has translation, a tilt/rotation, linear velocity, and angular velocity. Each frame, the program moves time forward a small step: gravity speeds it up downward, it drifts a bit (damping so motion doesn't go forever), and its straight-line speed updates its position. Spin updates tilt in a similar way. Integration is semi-implicit Euler. Velocities are updated with gravity and exponential damping (a simple stability/friction model), then position is advanced with the new linear velocity and orientation is advanced from the angular velocity. Since accumulating rotation is annoying in code, the code projects back: rotation matrix -> unit quaternion -> normalize -> rotation matrix. This renormalizes the frame each step and prevents long-run skew. We don't give every shard the same weight or "spin resistance." The code treats each shard's mesh as solid glass at a fixed density, then adds up contribution from all its triangles to get total mass and how hard it is to spin (inertia) from that actual shape. So a big chip is heavier and harder to twist than a tiny sliver, instead of pretending every piece is the same simple box.

Collisions. We detect ground-plane penetration by transforming shard vertices into world space and taking the minimum signed height along the ground normal. A coarse spherical bound from the centroid skips airborne bodies. Resolution pushes out along the normal, zeros normal velocity, and on first ground touch applies a small bounce and horizontal scatter. On later contact, we snap orientation so a body axis aligns with the normal and sleep the body to stop jitter. Smith's line of work often couples fracture events to dynamics. We use Voronoi breaks and hand-tuned kicks when shards spawn which is fast and easy to steer, but it's not a true energy-conserving simulation. VACD is mainly useful when you break a messy 3D object and need simple collision shapes, however our shards are flat outlines extruded to thin solids, so collision is already straightforward. We chose that simpler pipeline instead of a general 3D breakup method.

Rendering. We use OpenGL 2.1-style GLSL. The glass pass mixes view-dependent Fresnel (low reflectivity head-on, higher at grazing), specular from a scene light, tint and alpha, and environment-looking reflections by sampling a 2D background texture with direction-to-UV mapping on a sphere-like parameterization. It is not full path-traced refraction through thick glass, but enough to sell transparency and glints in motion. Separate simple shaders draw the ground, solid objects, full-screen background, and the intact panel.

Contributions from Each Member

Randy implemented post-shattering ground behavior so shards settle instead of snapping flat. Gentle impacts have almost no bounce, but harder ones increases to full restitution, which damps tiny hopping. Ground drag increases with sliding speed for every frame the shard stays in contact. In each PhysicsWorld::step, grounded shards get a restoring torque that tips them toward lying flat, and when both translational and spin rates fall below threshold after grounding, they sleep. He also implemented shard to shard physics after the break. PhysicsWorld::detect_collisions uses a sphere broad phase, then a vertex-in-sphere narrow phase to find penetrating contacts and their depth. PhysicsWorld::resolve_contacts applies two-body impulse resolution using each shard's inertia about the contact point, so heavy and light pieces seem realistic. Friction is a separate tangential impulse after the normal impulse. The active/sleep check is one-sided, so awake shards still generate contacts against sleeping ones. Finally, he wired tertiary fracture: when relative speed between two shards exceeds kShardFractureSpeedThreshold, the system queues a fracture on the larger shard.

Skylar implemented slow motion for the break sequence by exposing a slo_mo_ mode on DemoApplication with getters/setters. GlassDemoRenderer::keyboard_event maps S to cycle slo_mo_ through 0-1-2. In DemoApplication::update_and_render, nonzero modes apply a slow factor (3x for mild slowdown, 10x for stronger) by dividing the physics dt before stepping, approximating higher temporal sampling without changing the render frame rate. They also implemented glass shading. GlassRendererParams carries index of refraction, reflectivity, transparency, and tint, initialized to plausible glass values in DemoApplication::init and fed into the shader uniforms. In glass_renderer.cpp, the mesh is drawn with dedicated GLSL shaders. The fragment path combines Schlick Fresnel against an environment / background sample for reflections, Blinn-Phong-style specular from a single point light, and a subtle tint on the final color. Alpha rises for the reflection but stays low usually for the glass. The border region for the glass is more opaque using plane position, matching the look of framed real-world glazing.

Kyle implemented impact-directed shard motion so breaks feel like a real strike. In ShatterSimulation::spawn_shard_body, each shard gets an outward impulse whose strength falls off exponentially (e(-d/r)) with in-plane distance from the hit. The launch direction mixes the panel normal with the in-plane radial direction according to that falloff. Launch speed scales with impact energy, the falloff, and the chosen radial/normal blend, and shards pick up spin from the cross product of radial offset and panel normal so they tumble in flight. He also extended ground fracture so hard landings can split shards again instead of only bouncing. In PhysicsWorld::resolve_contacts, shards on first ground contact that exceed an impact-speed threshold and are still above a minimum size enqueue a fracture request and skip the usual bounce-and-scatter path. Shards below that radius floor always fall through to bounce regardless of speed. The existing Voronoi refracture path is also resued for each request after each physics step.

Mason contributed the core fracture and physics systems: 2D Voronoi fracture on the glass plane (impact-centered seeds), recursive breaks (placing sites only inside the chosen shard, rebuilding that region, removing the parent piece, and spawning new shards), and rigid body simulation (ground contact from mesh vertices with an air check, and one bounce then sleep to avoid jitter). He also put substantial work on the simulation engine the project runs on. They also handled milestone deliverables (slides, video edit, webpage) and helped with the proposal. For runtime controls and feedback, they implemented pause, reset, and an FPS counter.
